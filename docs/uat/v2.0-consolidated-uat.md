# UAT book: ProbeMatrix Learnings Coach v2.0, consolidated (Phases 3 to 6)

**Build under test: v2.0.0-rc.N (`pmlc 2.0.0rcN`).** Replace `N` with the release-candidate number you were given, for example `v2.0.0-rc.1` and `pmlc 2.0.0rc1`.

User acceptance testing (UAT) for v2.0, run once at the end, in the Claude app. Phases 3 to 6 are not tested one by one: each phase adds its own section to this book, and you run the whole book on the release candidate. A fix goes into the next release candidate (`rc.N+1`), and you re-run only the failed tests on it.

Every test tells you:
- what to paste;
- which file to attach;
- what you should see.

**Where the numbers come from.** Each phase's numbers come from a real run of the engine when that phase was finished. The Phase 3 numbers come from a run on 2026-10-20, on the inputs listed under Setup. That run printed `2.0.0a4`: the version number is raised only at release time, and nothing else changes with it. The Phase 4 numbers come from a run on 2026-10-21, the Phase 5 numbers from a run on 2026-10-24 and the Phase 6 numbers from a run on 2026-10-28 (see the start of each section). So wherever this book shows a version, you should see your release candidate's (`2.0.0rcN`, or `v2.0.0rcN` in page footers). If you are testing the Phase 3 alpha early, it is `v2.0.0-alpha.5` (`pmlc 2.0.0a5`).

Where a test depends on the agent's own writing or behaviour, it is a checklist, not exact text.

**Words used in this book** (one line each)
- **Engine:** the small program (`pmlc.py`) that the skills run to count, filter and check. The agent runs it for you.
- **Export:** the `.xlsx` file you download from ProbeMatrix for one investigation.
- **Finding:** one row of the export, such as `FND-0001`. **Evidence item:** one piece of evidence, such as `EVD-0001`.
- **Workspace:** the folder of files the engine builds from one export. Its outputs go in an `outputs` folder beside it; both sit in a **run folder**.
- **Pack:** one learning output (such as a board brief or a set of learning cards), written as a JSON file and turned into a web page (HTML) and a Markdown file.
- **Register:** the lessons-learned register, one row per learning, as a JSON file, an Excel workbook and a Markdown file.
- **LR-nn:** the number of one learning in the register, such as `LR-08`. On a page, a pack item that carries a register learning shows a **Learning LR-08** button.
- **Tier:** the level of the organisation that must act on a learning: T1 frontline, T2 supervisors and shift in-charges, T3 function and department managers, T4 site leadership, T5 corporate and board. (T9 means "not yet placed".)
- **Language check:** the engine's check of the wording (rules JC1 to JC12, such as JC1 personal names and JC2 blame words). An **error** fails the check; a **warning** does not.
- **Sign-off:** a person's record that they reviewed a pack or register. It records the role (never a name) and the date in the file.
- **Forced draft:** nothing can be signed off while the investigation is still in progress in ProbeMatrix, or while no finding has been edited by a person. The Hazira sample is both, so it always stays a draft.
- **DRAFT ribbon:** the "DRAFT" banner at the top of every page that a person has not approved.
- **Shared copy:** a masked copy for outside the organisation, made only after approval and legal clearance.
- **Embed mode:** how much of the investigation a page carries inside it: `cited` (the default) only the records the pack cites, `summary` the same without quotes, `full` everything relevant.
- **Hub:** the `learnings-coach` skill, where every request starts. It sets up the workspace, works out what you want, shows a numbered plan, and waits for your OK.
- **Plan:** the numbered list of steps for a request, made from a **preset** (a ready-made workflow, such as `leadership`) or from the audiences or skills you name. Each step is **done**, **todo**, or **planned** (it belongs to a later phase and is skipped).
- **Gate:** the check a step must pass before the next one starts: the pack or register check in strict mode, and, for a pack meant for outside the organisation, also an approved review by a person.
- **Strict mode** (`--strict`): some checks only warn by default; strict mode makes them fail.
- **Organisation files:** files your organisation fills in, never the agent: `adoption.csv` (did you accept each learning), `distribution.csv` (who each pack reached) and `verification.jsonl` (did each learning stick). The engine writes them blank and never overwrites one.
- **Comparator:** the numbered items (observations, root causes, recommendations, actions) of another report on the same event, with a map of which learning matches which item.
- **Run manifest:** a small record in the run folder (`run-manifest.json`) of what the run is for, its jurisdiction and its retention review date.
- **Purge:** deleting a run's working data after its retention date, while keeping the run manifest.

## Before you start

> - **Do a 5-minute dry run first:** P3-A1 and P3-B1 in conversation 1. If either fails, stop and report it before running the rest of the book.
> - **Paste every prompt block.** Some tests have a **Prompt 2** or **Prompt 3**: paste each one, in order, as its own message, after checking what the previous one showed.
> - **If the agent cannot write next to the uploaded file** (the upload folder is read-only), say: "Use `--root` with a writable working folder." The run is then made inside that folder. This is not a failure.
> - **The agent works on copies.** Uploaded files cannot be changed. So a prompt that changes a file asks the agent to copy it into the run's `outputs` folder (or the workspace) first and to work on that copy.
> - **Ask for the files.** When a test produces an output, ask: "Give me the output files to download." Open HTML pages in a normal browser (Chrome, Edge, Firefox or Safari, with JavaScript on), and `.xlsx` and `.csv` files in Excel.
> - **Never sign off for the agent's sake.** Only P3-I3 and P3-I5 tell the agent you reviewed a file. In P3-I3 the claim is deliberate: Hazira is forced draft, so the engine must still refuse. In every other test, do not say you reviewed anything.
> - **Usage limits.** The book needs 20 conversations. If you hit the app's usage limit, that is not a failure: stop, and carry on in the same conversation when the limit resets. If time is short, run conversations 1 and 2 first; conversations 3 to 7 (P3-A2 and the H tests), 8 to 10 (Phase 4), 11 to 15 (Phase 5) and 16 to 20 (Phase 6) can follow on another day. Conversation 12, your own 9M interview, takes the longest: about an hour.

**How to read "Expected".**
- Exact text in `code` should appear word for word in the agent's reply or in the engine output it shows you.
- If the agent only summarises, ask: "Show me the engine's exact output."
- Long paths are left out; only the end of each line matters. `…` stands for the part of a path or line left out.
- A date written as `<today>` is the day you run the test, as `YYYY-MM-DD`.
- "Exit code" is the number the engine ends with: 0 means OK, 1 means problems found or refused. Ask the agent for it if it does not say.

## Phase 4: outputs

Phase 4 turns a pack into the formats people use: a Word document and a Word board paper, PowerPoint slides, an email digest, an actions CSV for Excel, print layouts (cards, toolbox talk, checklist) with QR codes, a learner view that hides the answers, quiz files for a learning system (GIFT and SCORM), a Hindi translation, graph files (SVG, GraphML, PNG) and your organisation's brand.

**Where the Phase 4 numbers come from.** A local run on 2026-10-21, on the Hazira sample and the inputs listed under Setup. That run printed `2.0.0a5`; on the release candidate you should see `2.0.0rcN` and `v2.0.0rcN` in footers. A file size moves by a few bytes with the version number and the date, so sizes are given as "about". Page counts in Word may differ by a page from the counts here, which come from LibreOffice and Chrome.

**More words used in this section** (one line each)
- **Format:** a kind of file the engine writes from a pack, chosen with `--format` (for example `docx`, `pptx`, `email`, `csv`). The default is `html,md`, as before.
- **Layout:** a print-ready page, chosen with `--layout` (for example `cards`, `toolbox`, `checklist`, `paper`). It is written beside the normal page as `<pack>.<layout>.html` and never replaces it.
- **Learner view:** a copy of a pack without the answers, for people taking a quiz or a session.
- **GIFT:** a plain-text quiz format that Moodle and other learning systems import. **SCORM:** a zip package that a learning system (LMS) runs and scores.
- **Brand:** a small `brand.json` file with your organisation's name, one accent colour and a logo. The status line and the footer stay fixed.

## Phase 5: deeper analysis

Phase 5 adds nine skills that look harder at one investigation:
- an evidence scorecard and a register of open questions;
- a profile of the latent conditions and a review of why earlier warnings never led to change;
- a 9M (nine Ms) interview with you;
- a review of how strong the recommendations are;
- learnings for HR and workforce planning, proposals for the risk register, and a crosswalk to ISO 45001 and RBPS.

It also extends five existing skills: missed opportunities, the incident-day sequence, an alarms theme, an insurer's view for auditors and an industry reference pack.

**Where the Phase 5 numbers come from.** A local run on 2026-10-24, on the Hazira sample and the inputs listed under Setup. That run printed `2.0.0a6`; on the release candidate you should see `2.0.0rcN`. Every number here is a count the engine makes, so it should match exactly. Text the agent writes (a learning, a question, a direction for change) is checked with a list, not word for word.

**More words used in this section** (one line each)
- **9M:** nine parts of a work system that a condition can belong to: M1 Manpower/Mindpower (people readiness), M2 Medium (the work environment), M3 Method, M4 Mission, M5 Measurement, M6 Management/Money, M7 Machine, M8 Material, M9 Maintenance.
- **Seed:** the engine's first pass, which scores every finding against the nine Ms before the interview starts.
- **Session:** the record of the 9M interview: each question, its suggestions and your answer, kept in `nine_m_session.json` in the workspace.
- **Replay:** a scripted session that picks the first suggestion at every question. The sample uses one; its pack says `Answers chosen for demonstration, not by the organisation.`
- **Banner:** a fixed sentence that a pack must carry word for word. The check fails if a single character differs.
- **Single-source / document-only:** a finding backed by one evidence item, or by documents only (no witness, log or inspection).
- **Strength band:** how strong a recommended change is: `stronger` (elimination, substitution, engineering), `intermediate` (most administrative changes) or `weaker` (training, PPE, and administrative changes such as a reminder or a memo).
- **Weak fix for a deep cause:** a learning whose cause sits at HFACS level 3 or 4 (supervision or organisation) but whose recommendations are all weaker.
- **Knowable then:** what the records showed at the time of an earlier warning, so the review is not judged with hindsight.
- **Crosswalk:** a table that maps the learnings to the clauses of a standard. It is an aid to assurance, never a compliance opinion.

## Phase 6: sharing, sessions, methods and the library

Phase 6 adds seven skills that take the learnings beyond the investigation team:
- a graded **safety alert** for other sites and peer organisations;
- a **"could it happen here?"** self-assessment that each sister site fills in and returns, and a consolidated view of the returns;
- a ten-minute **safety-moment deck** for a shift-start session;
- a **learning-team** session plan, with questions about work as it is really done;
- a **restorative response guide** for the leaders who support the people involved;
- a **systemic AcciMap** that places the findings on six levels, from government to equipment;
- a **learning-effectiveness plan** that says what to check, and when, after the organisation adopts each learning.

It also starts the **library**, where an organisation keeps its learnings from many investigations. In v2.0 the library only stores and publishes. The views across several incidents come in v2.1.

**Where the Phase 6 numbers come from.** A local run on 2026-10-28, on the Hazira sample and the inputs listed under Setup. That run printed `2.0.0a7`; on the release candidate you should see `2.0.0rcN`. Every number here is a count the engine makes, so it should match exactly. Text the agent writes (an alert, a self-check, a question) is checked with a list, not word for word. File sizes move by a few bytes with the version number and the date, so they are given as "about".

**More words used in this section** (one line each)
- **Grade:** how urgent a safety alert is: `alert`, `notice` or `information`. It shows as a `Grade:` line under the title.
- **Urgency:** the register's own grade for a learning. When the register has none, the agent suggests a grade and asks you.
- **Mode:** who a safety alert is for: `internal` (this site), `sister-site` (the organisation's other sites) or `industry` (other organisations).
- **Review copy:** an alert for other sites or the industry that has not been approved yet. Every format opens with a line saying it may not leave the organisation.
- **Self-check:** one condition a sister site looks for in its own plant, with the records that would show it and where to look.
- **Return:** the Excel sheet a site fills in for the self-assessment: its name, and for each self-check the answer (`present`, `partly`, `absent` or `n/a`), its response and the assessor's role.
- **Work as imagined, work as done:** what the procedures say happens, and what the people doing the job say really happens.
- **Learning team:** a meeting of the people who do the work, run by a facilitator who did not investigate, to learn how the job really goes.
- **Second victim:** a worker who is hurt, emotionally, by having been involved in an incident.
- **AcciMap:** a map of where the causes sit in the wider system, on six levels: 1 government, 2 regulators, 3 company, 4 technical and operational management, 5 the work, 6 the equipment.
- **Inferred:** placed on a level by a rule (from codes and departments), not because the export says so. A person confirms it.
- **Kirkpatrick levels:** four steps of a learning taking hold: L1 communicated, L2 understood, L3 applied, L4 effective.
- **Offset:** a time counted from the day the organisation adopts a learning ("90 days after adoption"), never a calendar date.
- **Library:** a folder of JSON Lines files (`.jsonl`) that keeps each published learning under a fixed `LL-` number, such as `LL-000001`. A real site name is kept in the library's `private` folder only, and a code such as `S01` is used everywhere else.

## Severity guide

| Severity | Meaning | Examples |
|---|---|---|
| **Blocker** | Wrong or unsafe output | a crash; a number that differs from this book; a learning with no citation; a personal name or a blame word in an output; the agent signs off by itself, or writes an owner, a due date or an organisation's response; an organisation file overwritten or blanked; purge deleting without `--yes` or outside a run folder; a shared copy that shows a name, a company, a tag, a time or a full date; a library line outside `private` that shows a real site name, a listed name or a full date; a site ranked or scored in the consolidated view; sign-off accepted on Hazira |
| **Major** | A feature does not work, but there is a workaround | the hub runs steps before your OK, or asks several questions at once; a skill does not start, but naming it works; a pack fails `check-pack --strict` and the agent fixes it on request; a manual page is missing |
| **Minor** | Wording or layout | an awkward heading; a hint that is hard to follow; a table that wraps badly on a phone; a confusing but harmless profile flag |
